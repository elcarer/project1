# Документация игры «Открытый мир RPG» (project1/engine)

Игровая документация проекта `elcarer/project1`: открытый мир с деревнями, квестами,
генерируемыми подземельями и RPG-прогрессией на движке PixiJS 8.19 + собственный ECS.
**Работа над игрой приостановлена 2026-09-16** (версия зафиксирована коммитом
`20aa838` — «Правки из полного игрового прогона»).

Документы проекта:
- **GAME.md** (этот файл) — всё про ИГРУ: контент, боевка, квесты, умения, меню,
  подземелья, арт-пайплайн и стиль, игровая история и заделы.
- **ENGINE.md** — про движковую часть этого репозитория (ядро ECS, dualgrid,
  редакторы, производительность).
- **zero_engine** — самостоятельная копия ЧИСТОГО движка (без игрового контента)
  для подключения к будущим проектам: https://github.com/elcarer/zero_engine,
  локально `D:\ZCode\zero_engine`. Копия сознательная: `engine/` этого репозитория
  не переподключался на zero_engine, чтобы замороженная игра осталась нетронутой.

## Как запустить игру

Открыть `engine/index.html` двойным кликом (работает с `file://` — все ассеты вшиты)
или по адресу `http://127.0.0.1:8791/index.html` на сервере разработки. Параметры:
`index.html?w=500&h=500&seed=7` — размер и сид мира; `?filemode=1` — прогон
file://-веток (вшитые EMBED-ассеты) по http; `?raf=timeout` — requestAnimationFrame
на setTimeout (автотесты на скрытой/перекрытой панели, без реальных кадров).

Управление: WASD/стрелки/джойстик — движение, атака автоматическая (враг в зоне
оружия), клавиши **1–3** — умения, **L** — журнал квестов, **P** — пауза,
**F3** — оверлей отладки, колесо — зум.

Для разработки — статический сервер с запретом кэша (обычный `python -m http.server`
кэширует эвристически — правки «не применяются»):

```bash
cd engine && python nocache-server.py 8791
```

**Пересборка ассетов после правок PNG/JSON в `images/`** — `python images/rebuild_registry.py`
(сухой прогон — `--check`): реестр объектов, вшитые ассеты игры для file://
(`scripts/embedded_assets.js`), вшитые иконки умений (`embedded_abilities.js` —
дополнительно `scripts/make_embedded_abilities.py`), портреты лобби
(`make_embedded_lobby.py`), вшитые тайлсеты редактора карт.

## Персонажи из forWork: пакер сырых полос (scripts/pack_characters.py)

Сырые заготовки лежат в `forWork/<enemy|hero>/<имя>/{move,attack,others}/*.png` —
по одной ГОРИЗОНТАЛЬНОЙ ПОЛОСЕ на анимацию, 4 кадра в полосе, спрайты стоят на
нижней кромке. `python scripts/pack_characters.py` склеивает их в листы 5×11
формата волка: `images/sprites/<имя>_<клетка>.png` + `.json` (fps 8). Размер
клетки: 64 (контент ≤64 — центр по X, низ с зазором 2px), 128 для кадров
128×128 (копия как есть). Папка `abil` у героев не входит (не стандартный набор).

- Контакт-листы всех персонажей (сетка, подписи, шахматный фон) пишутся в
  `tmp/forwork_preview/` — обязательная визуальная проверка каждого кадра.
- У rat нет `wait`, у spider/spiderRed нет `wait` и `damage`: wait синтезируется
  из кадра 0 `move/front` (1 кадр), damage просто отсутствует в манифесте
  (`play()` вернёт false). Строка в листе при этом остаётся пустой — формат 5×11
  у всех одинаковый.
- Пограничный контроль: полосы режутся по границам 4 колонок; колонки разрезов
  с плотной непрозрачностью печатаются предупреждением (возможный разрез по
  спрайту) — финальный арбитр всё равно контакт-лист.

**Листы персонажей** (23 врага + 4 героя) грузятся модулем assets
(`EMBED.chars` на file://). Витрина-строй NPC из тестов удалена из сцены
(мешала проверке мира и ИИ) — теперь на карте только герой и ИИ-враги
(см. «ИИ врагов»), а листы персонажей расходуются на боевые единицы.
Механизм рядов ног (`creatureRowFollow`) и `freeSpotNear` — общий.

## Снаряды (modules/projectiles.js + data/attacks.js)

// АТАКИ И СНАРЯДЫ — привязка «персонаж → атака → снаряд» (data/attacks.js).
// ATTACK_CONFIGS — типы атак: kind — «melee» (эффект ПЕРЕД персонажем, не
// двигается, анимация однократно, время жизни = длина анимации) или «ranged»
// (снаряд вылетает и летит, гаснет по lifetime из атаки персонажа); reach —
// «зона потенциальной достижимости оружия» (px): автоатака срабатывает, когда
// цель вошла в радиус (у ИИ — дистанция остановки для стрельбы).

- **Листы снарядов** собирает `scripts/pack_projectiles.py` из
  `forWork/attacks/<атака>/*.png`: `all.png` — универсальная анимация,
  `front/back/left/right.png` (+ диагонали у knife) — своего направления;
  ОДИН лист `<атака>.png` + `.json` на атаку, строка = направление, формат
  манифеста как у персонажей (грузится тем же `assets.loadCharacter`). Кадры
  сегментируются по прозрачным колонкам (ширина кадров внутри атаки гуляет);
  слипшиеся полосы чинятся переопределениями FRAME_COUNT_OVERRIDES («разделить
  на N равных»). Контакт-листы → `tmp/forwork_preview/projectiles/`.
- **Выпуск**: персонаж с привязкой (`projectiles.bind(id, вид)`) играет
  attack_* → на кадре `spawnTick` рождается эффект/снаряд: melee — из «груди»
  чуть впереди, стоит на месте (`vx/vy = 0`), `loop=false` — анимация
  проигрывается ОДИН раз и эффект гаснет (lifetime = кадры/fps); ranged —
  летит прямолинейно (`vx/vy` по направлению × speed), кадры крутит ядро
  (loop), по истечении `lifetime` гасится в пул своего типа. Сущность несёт
  только существующие компоненты (positionX/Y + spriteMap + animationSpeed +
  cullPad) — ноль новых бит; снаряды ходят по «рядам ног» и честно заходят
  за стволы.
- **Автоатака героя**: в сцене game герой сам бьёт ближайшего врага, вошедшего
  в reach его оружия (кулдаун 0.9 с, рефлексы сокращают); клавиши атаки нет.
  ИИ-враги атакуют так же: дальнобойные останавливаются на дистанции reach
  и стреляют, ближние подходят на 0.6·reach. Коллизии/урон — модуль combat
  (см. «Боевая и ролевая система»).
- `file://`: листы вшиты в `EMBED.proj` (пересборщик `make_embedded_assets.py`
  читает и `images/projectiles/`).
- В `__TEST`: `projectiles` (`TYPES/BOUND/PROJ/ACTIVE` — активные снаряды).

## Боевая и ролевая система (modules/combat.js + data/stats.js)

// Ролевая модель — формулы из образца forWork/countDopStats.js (без реликвий
// и инвентаря): 5 основных характеристик (Сила/Ловкость/Здоровье/Скорость/
// Мудрость) → по 3 вторичных стата от каждой. countLog(i) = trunc(((1+40/i)^
// (i/40) − 1)/(e−1)·100) — универсальный переводчик стата в процент: блок =
// countLog(Сила/2), крит = countLog(Ловк), мощь крита = 150 + 2·countLog(Ловк)
// (начинается со 150%), уклонение = countLog(Ловк/2), ХП = 10 + 5·Здоровье,
// подвижность/рефлексы и т.д. Опыт до уровня — кривая пользователя:
// xpToNext(lvl) = trunc(((1+10/lvl)^(lvl/10) − 1)/(e−1)·100) (15 → 100).

- **Битовый бюджет: ноль новых компонентов** (занято 30/32). ХП живут в
  компонентах `hp/maxHp` — их при загрузке страницы регистрирует modules/health.js
  (стиль того модуля устарел, но регистрация идемпотентна и переиспользуется).
  Ролевые данные (STAT/FACTION) — обычные массивы фабрики, как STATE в ai.js.
- **Разрешение удара** (`dealDamage`): уклонение (весь урон мимо, «уклон») →
  крит бьющего (урон × мощь крита, большая жёлтая цифра «N!») → блок
  (половина урона, серая цифра) → каменная кожа цели (`special.stoneskin` —
  кап урона за удар) → вычет ХП. После урона: наложение яда бьющего
  (`special.poison`) и событие `onDamaged` (зов соратников). Каждое событие —
  всплывающая цифра над головой (modules/fx.js, слой над объектами) + красная
  вспышка спрайта. Урон бросается при ВЫЛЕТЕ снаряда: `rollAttack(id)` →
  weaponMin..attack (attack = Сила), снимок едет на снаряде (`PROJ[].attack`),
  поэтому смерть стрелка в полёте не ломает попадание.
- **Особые способности врагов** (`special` в ENEMY_STATS, справочник —
  ENEMY_BESTIARY data/enemies.js). Активны: `stoneskin` (орк — кап 12/удар),
  `poison` (паук — тление 1 урона/с, зелёные цифры, может убить; убийство
  засчитывается отравившему), `call` (гоблин — колбэк `onDamaged` в game.js →
  `ai.alert(x, y, R)` поднимает соратников в радиусе из патруля в погоню).
  Остальные ключи бестиария (rage/reanimate/flame/shadow/dash/charm/howl/
  summoning/vampirism/crush/voidBlob/segmentation/invulnerability) — контент
  под данжи, механики появятся вместе со спавном этих видов.
- **Попадания**: melee-эффект бьёт разовым АоЕ (радиус 40) в момент появления;
  летящий снаряд бьёт первую противника под собой (радиус = size·0.3+4) и гаснет.
  Фракции: 0 — сторона героя, 1 — враги (снаряд бьёт только чужую фракцию).
- **Полоска ХП** — ребёнок спрайта (culling и «ряды ног» достаются бесплатно),
  показывается только когда ХП не полные. Контратака: выжив под melee-ударом —
  шанс ответить своим оружием (гвард 1.2 с против пинг-понга).
- **Смерть**: анимация death держит последний кадр (свой onComplete — штатный
  снял бы ctrlLock, и «труп встал»), корпус тает и убирается (спрайт мимо
  ядерного пула, `BOUND[id]=null`, колбэк `onRemove` чистит ряды ног и хендлы
  сцены). Герой вместо уборки возрождается через 2.5 с с полным ХП.
- **Опыт и уровни** (только герою): награда за вид (ENEMY_STATS[kind].xp),
  обучаемость может удвоить; на уровне растут основные статы (HERO_BASE.growth
  +2 всё), полный хил, пересчёт скорости (подвижность). Статы врагов —
  ENEMY_STATS (уровень/статы/weaponMin/награда) + разброска +0..1 при спавне.
- **Заделы на будущее** (считаются, но не применяются — способностей/дебафов
  ещё нет): сопротивление, выносливость (+% к лечению — применяется в heal),
  находчивость, сила воли, контрмагия. Применяются сейчас: подвижность
  (скорость), рефлексы (кулдаун автоатаки героя), обучаемость.
- **HUD героя** (правый верх): «Волк · ур. N · HP/Max» + полоски ХП и опыта
  (modules/hud.bar). Отладка: `debug.info["ХП"]`, в `__TEST`: `combat`,
  `heroStat()`, `heroDop()`, `giveXp(n)`.
- **Прицельность и классы дистанционных атак** (слова пользователя): летящий
  снаряд с 4 анимациями (front/back/left/right) летит СТРОГО по вертикали или
  горизонтали взгляда атакующего; под произвольным углом (например по
  диагонали, в цель) летят только снаряды с ОДНОЙ анимацией `all` — лист
  классифицируется при загрузке (`TYPES[].freeAngle`). Прицел `playAttack(id, aim)`
  применяют только all-снаряды (шаман staff, паукоид web, октопус octo,
  огр club и т.д.),
  осевые (bow, poison) его игнорируют — на диагоналях они целенаправленно
  промахиваются, это честное поведение класса. Привязки видов и kind атак
  выверены по образцу (см. раздел «Контент из образца»): гоблин и нетопырь —
  melee-укол кинжалом, орк — булава, огр — БРОСОК дубины (ranged, all-лист,
  свободный угол), шип — каменный удар вблизи, тёмный воин — копьё-снаряд.
- **Игровой шрифт** всех надписей (HUD, отладка, цифры урона) —
  `MixSerifCondenseRUS` из `forWork/*.ttf`, вшит base64 в `scripts/game_font.js`
  (генератор `scripts/make_game_font.py`; на file:// внешний ttf — чужой origin,
  data-URL работает всюду). game.js зовёт `await loadGameFont()` до первых
  PIXI.Text; дефолт fontFamily в modules/hud.js, fx.js, debug.js — `GAME_FONT`.
  Размеры с 2026-09-15 удвоены по требованию пользователя (24–28 базово,
  цифры урона 22/28, пауза 64); ширина полос героя 220/176 px.
- **UI-спрайты** (`images/ui`, исходники в `forWork/UI`): курсор игры —
  `cur.png` через CSS `body { cursor: url(...) 0 0, auto }` (остриё в пикселе
  0,0); рамка загрузки `bigBar.png` (407×64) + линия `loadBarLine.png` (315×24,
  в рамке на 46,20) — экран загрузки по центру на старте: `setStage(метка,
  доля 0..1)` тикает по этапам бута (тайлсеты → реестр → генерация → запекание
  → объекты → персонаж → враги), при входе в игру бар уничтожается.
  Полоски HUD героя — тоже спрайты (фабрика `makeSpriteBar` в game.js):
  ХП — `bigBar` + красная `hpBarLine` (220px, scale 0.54), опыт — `smallBar` +
  золотая линия (176px = на 20% короче, scale 0.8), центры полос — на общей
  оси симметрии. Полоски привязаны к ПРАВОМУ КРАЮ экрана: позиции
  пересчитываются в обработчике `app.renderer.on("resize")` — при изменении
  окна/фуллскрине остаются в углу (y: ХП 12, опыт 51; текст над полосками
  убран — уровень/ХП видны в оверлее отладки).
  ⚠️ ЛОВУШКА v8: заливку полос НЕ делать через Graphics-маску
  (`renderable=false` не отсекает линию) и НЕ через мутацию `texture.frame`
  (UV минифицированного билда не обновляются — линия всегда «полная»,
  вылезает за рамку). Рабочий способ — `PIXI.NineSliceSprite`
  ({left:14, right:14, top:10, bottom:10}): `width` = доля заполнения,
  середина растягивается, торцы не искажаются; у текстур PIXI.Assets нет
  `.clone()`. Красная `hpBarLine.png` — та же заливка в ХП-полосе; остальные
  спрайты папки (`hpBarLine` уже подключён, другие — под будущие полоски) на
  file:// вшиты в `EMBED.ui` (make_embedded_assets.py собирает images/ui).
- **Отладка без отрисовки**: `index.html?raf=timeout` подменяет
  requestAnimationFrame на setTimeout (до подключения Pixi) — игра грузится и
  тикает на скрытой/перекрытой панели (автотесты); на обычном запуске не
  включается. `?filemode=1` — прогон file://-веток (вшитые EMBED-ассеты) по
  http: тесты двойного клика без двойного клика.
- **Стартовое меню** (сцена "menu"): после загрузки мира игра открывает меню —
  фон `start.png` (cover на весь экран), колонка кнопок `button.png`
  (NineSlice, 280×60, слева на лесном краю арта): Продолжить / Новая игра
  (флаг sessionStorage + перезагрузка с новым сидом → бут открывает ЛОББИ) /
  Настройки / Выход (window.close, иначе экран завершения). «Настройки» —
  панель с переключателем полного экрана, Escape закрывает. Указатель на
  кнопках — cursor pointer, hover — подсветка. Кнопкам меню нужен
  `app.stage.eventMode = "static"`.
  ⚠️ ЛОВУШКА v8: NineSliceSprite в минифицированном билде НЕ хит-тестится
  (containsPoint всегда false — проверено boundary.hitTest) — интерактивность
  кнопки вешается на её КОНТЕЙНЕР с явным `hitArea = Rectangle(0,0,w,60)`,
  фон остаётся картинкой.
- **Лобби выбора героя** (сцена "lobby", после «Новая игра»): 4 карточки
  HERO_CLASSES (data/heroes.js) — портрет-кукла из образца
  (`images/heroes/doll/`, на file:// вшит EMBED_LOBBY —
  make_embedded_lobby.py), имя, 5 статов, описание, иконки боевых умений.
  Клик по карточке: `spawnHero(key)` (лист класса, ECS-сущность, привязка
  атаки, статы класса) → localStorage "heroKey" → сцена game. «Продолжить»
  подхватывает сохранённый класс, а при первом запуске ведёт в лобби.
  Раскладка: ряд из 4 карточек, на узких экранах сетка 2×2 с масштабом.
  Герой спавнится ОДИН раз за сессию; до выбора класса `heroId === null` —
  ai.getPlayerPos возвращает «бесконечно далёкую» точку, камера держит точку
  спавна, сцена game не работает без героя. Волк героем больше не является —
  он монстр (ENEMY_STATS.wolf, ~16% лесных спавнов, EMBED.wolf на file://).
  ⚠️ ЛОВУШКИ file:// (репорт пользователя, чинились 2026-09-16):
  (1) `newGame` собирал адрес из `location.pathname` ("/D:/...") — Chromium
  блокирует с «Unsafe attempt to load URL» — навигация только ОТНОСИТЕЛЬНЫМ
  адресом ("index.html?w=...&seed=...");
  (2) `textureFromDataURL` возвращает ПРОМИС — `new PIXI.Sprite(промис)` и
  присвоение промиса в `sprite.texture` (иконки панели: await был пропущен)
  ломают рендер/размеры с «Cannot read properties of undefined (reading
  'width')» — await обязателен везде; ветки file:// прогоняются по http
  параметром `?filemode=1`.

## Квесты (modules/quests.js + data/quests.js)

Цепочка «Путь вожака стаи» — 10 последовательных заданий, данные отдельно от
логики (`data/quests.js`: `QUEST_CHAIN` + `KIND_RU`). Активным всегда ровно
одно задание; следующее открывается после выполнения предыдущего. NPC нет —
модуль сам объявляет задания. Состояние сессионное (сохранений нет).

Типы целей: `kind: "rat"|…` — убить N врагов вида (ключ `ENEMY_STATS`),
`kind: "any"` — N любых врагов, `level: N` — достигнуть уровня N. Награда
(`reward`) — опыт через `combat.giveXp`.

- **События**: убийства героем приходят от боя — `combat.js` зовёт колбэк
  `onKill(killerId, victimId)` в конце `awardKill` (только реальные награды за
  убийство; вид жертвы game.js берёт из массива `enemies` — жертва покидает
  его позже, при уборке трупа). Задания «достичь уровня» модуль опрашивает сам
  каждый кадр (`combat.stat(heroId).lvl`). Тик — ТОЛЬКО в игровой сцене
  (`quests.update(ticker)` в scenes "game"), не через addSystem: объявления не
  тикают в меню/паузе.
- **Интерфейс** — свой контейнер в app.stage (`show(false)` в сцене menu):
  трекер активного задания под полосками ХП/опыта справа (300px, правый край
  при resize через `place()`); журнал всей цепочки по клавише **L** (Escape
  закрывает; маркеры: зелёный — выполнено, жёлтый — активно, контур — закрыто;
  внизу — описание активного); объявления — очередь плашек сверху экрана
  (2.8 с, затухание). Прогресс убийств дублируется всплывашкой «3/5» над
  героем (fx). Первое задание объявляется при входе в игру.
- **Награды и баланс**: награда ≈ половина опыта за целевые убийства; цепочка:
  крысы ×5 → уровень 4 → гоблины ×6 → пауки ×4 → дворфы ×4 → шаманы ×2 →
  орки ×5 → любые ×10 → огры ×2 → любые ×20 (итого ~485 опыта наградами).

## Способности героя (modules/abilities.js + HERO_ABILITIES)

У каждого класса — боевой набор из 3 активных умений (адаптации умений
образца, HERO_ABILITIES в data/abilities.js), панель слотов внизу по центру
с клавишами **1–3** (подсказка управления дополнена).

- **Данные**: `{ key, name, icon, cooldown, params, desc }` — параметры
  отдельно, механика — в модуле (RUN по ключу, 8 механик): снаряд в
  ближайшего врага (fireball), АоЕ-волна с замедлением (frost), метеорит по
  площади с отложенным падением (meteor, тик в update — заморожен на паузе),
  рывок по взгляду с уроном (dash/charge — от подвижности или силы), веер
  ножей (fan, 8 строк анимации knife по углу), притяжение врага (pull — урон
  не зависит от того, удалось ли дотащить), ускорение (haste — applySlow с
  mul > 1), лечение (heal — при полных ХП каст не тратится), казнь (execute —
  добивание врага ≤35% ХП).
- **Механики**: снаряды выпускаются прямым `projectiles.spawn` с СНИМКОМ
  урона владельца (`attack: { base, critPower }`) — тот же путь, что у
  автоатаки: умения могут уклоняться/критовать/блокироваться и убивать
  (килл засчитывается квестам). «Нет цели» — каст не тратит кулдаун.
  Замедление/ускорение — `combat.applySlow(id, mul, dur)` (STAT.slowT/slowMul,
  скорость пересчитывается из базовой; на время буст погони ИИ ×1.25
  пропадает — приближение).
- **UI**: слот 52px — Graphics-рамка (fill 0x140f08/stroke 0x6b4a2f, готовый —
  stroke 0xffd98e), иконка Sprite, тёмная шторка кулдауна сверху (высота =
  доля остатка) + секунды по центру (целые, ниже 1с — десятые), цифра клавиши
  в углу. `place()` на resize; `show(false)` в меню/лобби, `show(true)` в игре.
- **ТИК ТОЛЬКО В ИГРОВОЙ СЦЕНЕ** (как квесты): `abilities.update(ticker)` из
  scene update — на паузе кулдауны и метеориты заморожены; клавиши читаются
  там же.
- **Иконки на file://**: генератор `scripts/make_embedded_abilities.py`
  вшивает иконки боевых наборов в `scripts/embedded_abilities.js` (глобаль
  EMBED_ABILITIES, 12 иконок) — новое умение: добавить его icon в список
  генератора и перезапустить. По http — живые файлы images/abilities.
- Ноль новых компонентов: кулдауны — объекты слотов фабрики. `__TEST`:
  `abilities`, `abilitiesState()` (снапшот кд).

## Игровое меню (modules/gamemenu.js): очки, дерево, библиотека

Полоса из 6 кнопок сверху слева (видна только в сцене game): **Экипировка /
Умения / Журнал / Карта / Библиотека / Настройки**. Клик открывает панель
(сцена "panel"): мир на паузе (`setWorldPaused(true)` — системы модулей
заморожены через `gatedAddSystem`, ядро рендера работает), Escape/крестик —
закрытие. Кнопка «Пауза» (P) тоже замораживает мир целиком (раньше ИИ продолжал
стрелять — исправлено той же обёрткой).

- **Прогрессия**: за уровень герой получает **+1 очко характеристик** и
  **+1 очко умений** (combat.addXP; автоматический рост статов убран —
  growth у героя null). Очки характеристик тратятся во вкладке «Экипировка»
  (`combat.allocateStat`: prim++, пересчёт dop, прибавка ХП сверху текущего).
- **Дерево умений** (вкладка «Умения»): сетка узлов класса (x/y из
  ABILITY_TREES), связи prev→next (OR — достаточно одного предка), уровни
  узлов 1..maxLvl. Изучение — `combat.learn` (валидация очков/предков/потолка).
  Привязка эффектов: HERO_ABILITIES (активные, `node`+`mech`) и
  HERO_TREE_PASSIVES (пассивки) в data/abilities.js. Узлы без эффекта в
  открытой зоне («подземелья»: ключи/комнаты/ловушки) изучаются как проводка
  дерева, эффект спит до данжей. Изученные АКТИВНЫЕ умения встают в слоты
  панели 1..N (modules/abilities.js, syncSlots), уровень узла усиливает
  эффект (lvlDmg/lvlHeal/lvlBonus); кулдаун = base×(1−рефлексы/100) −
  «Прочитанный гримуар».
- **Пассивки** (combat.dealDamage читает STAT[hero].passives — плоский словарь
  {имя: уровень}, собирает game.js `recomputePassives`): броня (−N плоско),
  Противодействие (кап урона 4−N), Аура возмездия (ответный урон атакующему),
  Удар в спину (melee с противоположной стороны взгляда жертвы, +50%×N),
  Отравленное оружие (яд N сек), Облик мстителя (лечение за убийство),
  Ветряной щит (отброс атакующего — нужен blocked в createCombat),
  Отравленный лёд (Мороз травит), Прочитанный гримуар (−N с кулдаунов).
- **Журнал** — лог событий забега (убийства/уровни/открытия библиотеки,
  game.js `logEvent`, последние 100) + состояние цепочки заданий.
- **Карта** — мини-карта мира (canvas W×H: вода/лес/открытая местность,
  `getMapImage` в game.js, строится один раз) с меткой героя.
- **Библиотека** — бестиарий ENEMY_BESTIARY: карточки открываются за первое
  убийство вида; зачёт в localStorage "libraryKinds" — живёт между сессиями
  (как в образце). Неизвестный вид — «???».
- **Настройки** — полный экран, возврат в главное меню.
- Иконки узлов дерева — images/abilities/<класс>/<номер узла>.png (кэш
  menuIcons в game.js; на file:// — EMBED_ABILITIES, список в
  make_embedded_abilities.py). `__TEST`: `gamemenu`, `learn(idx)`,
  `allocate(key)`, `gameLog()`, `libraryUnlocked`.

## Подземелья: генерируемые этажи (data/dungeon.js + carve в game.js)

В дальнем углу карты (регион 46×34 клеток, `DUN.x0/y0`) — **генерируемое
подземелье** из 3 этажей: случайные комнаты (до 9, 4..8×4..6) соединены
Г-образными коридорами ширины 2, кайма стен (`generateDungeonLayout`,
детерминизм от сида; проверено: весь пол достижим BFS-ом от входа).

- **Запекание**: планировка рисуется ПОВЕРХ природного пола тайлсетом
  `dungeon_dirt.png` (двойная сетка «пол ↔ стена», генератор
  `scripts/make_dungeon_tileset.py` — 16 комбинаций квадрантов, стены —
  кирпичные блоки с окантовкой к полу). `carveDungeon(depth)` пишет
  cornerTex региона (tileIndex с outside=1 — внешний периметр замкнут) и
  заполняет `dungeonWall` (Uint8Array) — `blocked()` считает стены данжа
  непроходимыми. Объекты мира/деревни/дикие споты в регионе не генерируются
  (фильтры `inDun`).
- **Вход/выход**: пещера (`cave_rock`) в 25..55 клетках от спавна героя —
  подход вплотную (26px) телепортирует на этаж 1 (перезарядка портала 2.5 с,
  герой появляется РЯДОМ с порталом выхода, не на нём). Внутри: портал
  выхода (`rune_gate`) в комнате входа и портал вниз в самой дальней комнате
  (этапы 1→2→3; на 3-м этаже дна вместо спуска — элитный вампир). Выход
  возвращает к пещере.
- **Гарнизон**: 1–2 врага на комнату, пул по глубине: 1 — bat/spike/spiderman,
  2 — mummy/hound/imp/bat, 3 — succubus/vampire/dark/hound (+вампир-страж).
  Статы видов — ENEMY_STATS, поведение — общий ИИ. При спуске гарнизон
  и порталы пересоздаются (`despawnGarrison` — спрайт+ECS+ряды+enemies),
  планировка перегенерируется, `tiles.rebuild()` + мини-карта сбрасывается
  (mapTex=null; на карте «Карта» данж рисуется серым с планировкой).
- Этажи бесконечной вложенности нет: глубина 1..3, переходы через порталы
  «стоянием вплотную» — дополнительной кнопки не нужно.

## Арт-пайплайн и стиль спрайтов

Раздел перенесён из рабочей памяти (2026-09-16) — правила и рецепты, выработанные
с пользователем при создании спрайтов игры.

### Стиль рисовки (128px+): плавные формы, не блоки

После воина 128×128 пользователь (2026-09-11): «рисуешь слишком крупными
пикселями… сделай с менее угловатой рисовкой и более плавными линиями».
Крупные прямоугольные заливки (блоки 8–30px) читаются как угловатый пиксель-арт;
на 128px ждут плавные формы и мелкую детализацию.

Рисовать по образцу `engine/scripts/drawings/necromancer.js` (некромант,
коммит 28bc1c7; варвар `barbarian.js` — коммит 2874e33, финал качества — 427dcd9):
- эллипсы и квадратичные кривые Безье вместо прямоугольных блоков;
- детализация 1–2px (пряди, канты, тени);
- автообводка силуэта 1px в пустые пиксели у контура (изолированные точки
  свечения не обводятся); свечение/эффекты — ПОСЛЕ обводки.

Обязательные требования к качеству (правки пользователя при варваре/некроманте):
1. **Тени**: форменные тени при свете СВЕРХУ-СЛЕВА (блик-полосы сверху-слева,
   теневые полосы снизу-справа, переходы дизерингом) + наземная тень под ногами
   в КАЖДОМ кадре (мягкий рваный край — клетка по периметру эллипса).
2. **Отражения**: `flipX()` — ПОСЛЕДНЯЯ операция кадра, после всех эффектов
   (иначе «персонаж отразился, а эффект остался на старом месте»).
3. **Перекрытие эффектов телом**: удар «по ту сторону» фигуры (вид сзади)
   рисуется ДО тела (хук `behind`) — силуэт частично перекрывает эффект;
   поверх (`front`) только то, что реально в воздухе. За тело убирать ВСЁ,
   включая свечение и след дуги.
4. Оружие не закрывает лицо (лезвие топора 60px накрыло голову; рабочий размер
   ~17px от втулки, древко смещено от лица).
5. **Вид сзади прячет ВСЁ переднее**: пряжка ремня, оружие и кисти перед телом
   со спины скрыты полностью — не должны выглядывать в просвете между ног или
   торчать сбоку. Снаружи только края эффекта (пыль/свечение по контуру) и то,
   что реально в воздухе над силуэтом.
6. **Наземная тень НЕПОДВИЖНА**: не добавлять bob тела к y тени. Программная
   проверка — полоса тени в нижних рядах идентична во всех кадрах ряда.
7. **Гейты опциональных частей — по смыслу**: флаг включения детали должен
   совпадать с флагом её отключения (фантомное «второе лезвие» в death возникло
   из-за `!o.noArms` при отключении только `noAxe`). В кадрах, где деталь
   убрана, проверять отсутствие всех её частей.

Для 64px-персонажей — коллизия «ног» вдвое уже тайла (7×5 у волка 64px),
зум 2.5; формат листа 5×11: wait(3), walk/attack/death/damage по направлениям
(см. «Стандартный набор анимаций» в ENGINE.md).

### Визуальная верификация кадров (постоянное правило)

После генерации спрайтов/анимаций (рисовальщики в `engine/scripts/drawings/*.js`)
ВСЕГДА смотреть каждый кадр и чинить артефакты до завершения задачи.

- Цикл: сгенерировать → контрольный лист всех кадров (canvas, сетка, подписи
  рядов) → сохранить через POST /save → посмотреть → чинить → повторить.
- Типовые артефакты: не вызван `E.clear()` перед фазой (фазы накапливаются —
  призрачные линии, старые позы); примитивы перекрывают лицо; зеркальные виды
  теряют несимметричные детали (меч без кисти руки); отрицательные координаты
  обрезаются холстом; эффекты удара не в том слое (см. правила слоёв выше).
- Чек-лист по находкам пользователя: (1) зеркальные ряды — эффект отражается
  ВМЕСТЕ с персонажем (flip последним); (2) вид сзади — передние детали скрыты,
  эффект за телом перекрыт силуэтом; (3) наземная тень статична (сравнить
  полосу тени программно); (4) death — нет дублей деталей из других поз;
  (5) направление взгляда ПОКАДРОВО (среди лево-смотрящих встречаются
  право-смотрящие кадры); (6) замкнутые карманы фона (между корпусом и руками,
  пах, пасть) не берутся фладфилом от краёв — удалять ВСЕ карманы точного цвета
  фона без исключений по размеру: цвет фона внутри силуэта = невырезанный фон,
  не «дизайн костюма».
- Контрольный лист проверять на СООТВЕТСТВИЕ ЗАДУМАННОМУ ПЕРСОНАЖУ, а не только
  на артефакты (прецедент: постобработка мага с фолбэком на префиксы жрицы
  собрала жрицу). При переиспользовании скриптов сборки жёстко ограничивать
  префикс источников текущим персонажем.
- Проверка пикселей: `E.frameData(row, i)[y * size + x]`; `E.rows()` возвращает
  ЧИСЛО кадров (не массив) — для данных `E.frameData(row.name, f)`.
- **Предпроверка нового рисовальщика в Node со стабом редактора** (px/get/rect/
  clear/flipX/resize/renameRow/addRow/setRow/setFrame/newFrame/deleteFrame/
  frameCount/rows/silent) ДО запуска в браузере — ловит бесконечные циклы
  (прецедент: линия с дробными координатами → Брезенхэм не достигает точного
  равенства → вечный цикл, страница редактора замерзает).
- Контакт-листы собирать на светлом/пурпурном фоне: чёрный прячет тени и
  полупрозрачный мусор. fullPage-скриншот может склеиваться артефактно —
  проверять реальное дублирование запросом DOM.

### Источники анимаций (решение пользователя, 2026-09-12)

Генерация анимаций через SDXL/t2i НЕ подходит: чистый t2i не даёт межкадровой
консистентности (ноги почти не двигаются, детали плывут). Анимации стандартного
набора собирать двумя путями:
1. нарезка готовых спрайтшитов (вервольф-конвейер, см. «Cutout-сборка»);
2. процедурная рисовка (варвар/некромант — рисовальщик с эллипсами, кривыми,
   флагами видов).

SDXL+LoRA стек — только для СТАТИЧНЫХ спрайтов (портреты, предметы, тайлы,
одиночные существа). `mage_sdxl_128` остаётся в репо как тестовый артефакт.

### Cutout-сборка из сырых ИИ-листов (оборотень, коммит 7795e5a)

Конвейер `D:\ZCode\ComfyUI\werewolf\{extract,assemble}.py` →
`engine/images/sprites/werewolf_128.png`. ИИ-генераторы отдают сырые листы со
слипшимися спрайтами, зернистым фоном и мусором; ручная нарезка не масштабируется.

- Сегментация: `scipy.ndimage.label` по дистанции до медианного цвета границы
  > 45 (фон мерить патчами). Мелкие осколки (эффекты) вливать в крупные боксы.
- Слипшиеся ряды: разрез по четвертям с локальным минимумом плотности fg ±40px.
- Дубли кадров: матрица mean-abs-diff нормализованных альфа-bbox, пары <5 = дубли.
- Белая грунтовая линия внизу ряда: счищать строки снизу, где >50% ширины светлых
  (min RGB>195) пикселей — до bbox-кропа.
- Дизерные ИИ-эффекты (рой точек) не спасает ни фильтрация, ни closing/fill —
  рисовать программно (дуги PIL) и оверлеить на кадры атаки.
- Один глобальный SCALE по самому высокому стоящему кадру; тень статичная;
  зеркала левых рядов — в конце.

### Уроки t2i-генерации на SDXL (mage_sdxl_128)

SDXL base 1.0 + LoRA Pixel Art XL + Grid Generator (триггеры grid2x2/3x3/4x4,
вес 1.5) на GTX 1060 6GB ~3.5 мин/кадр 1024²:
- без grid-триггера модель рисует плотные листы с крошечными (~70px) фигурами;
- ключинг серого фона по RGB-дистанции не работает (тёмная роба ≈ тёмный фон):
  фон = «серость» (chroma<18, |lum−lum_bg|<30) + фладфилл от краёв; карманы
  удалять только чисто-серые;
- коричневая «земля» под ногами лечится негативами ground/dirt/soil/patch;
- grid-LoRA тянет «разные ракурсы одной позы» — резать 9–16 клеток, отбирать
  нужный ракурс;
- смерть «лёжа» t2i не генерит — финал программно (поворот стойки на 90° у земли
  + затемнение); спиновые ряды темнее — brighten ×1.28; источник атаки часто
  смотрит влево — mirroring-флаг в сборщике.

### Локальный ИИ-стек ComfyUI (D:\ZCode\ComfyUI) — концепты и референсы

Установлен 2026-09-12 (пользователь одобрил ИИ-ассистированный спрайтворк).
Стек: Retro Diffusion base (SD 1.5) + ControlNet openpose/depth + IPAdapter Plus;
venv Python 3.13, torch 2.14.0+cu126 (sm_61 на GTX 1060, ~20–25 с на 512² @26
шагов). Запуск: `venv\Scripts\python.exe main.py --port 8188`, API `POST /prompt`,
вывод в `output\`. HF троттлит соединение (~40KB/s) — параллельный загрузчик
диапазонов (32–40 конн ≈14MB/s), реальный размер проверять по HEAD
`X-Linked-Size`. Готчи: списки моделей кэшируются до рестарта; re-queue с тем же
префиксом пишет `_00002_` (постпроцесс берёт последний); сервер НЕ пайпить в
`head` (SIGPIPE убивал nocache-server). IPAdapter: input `ipadapter_file`,
`weight_type: "linear"`, вес ≤0.5 — гармонайзер палитры, ≥0.8 — якорит внешность
и блокирует переключения видов.

Валидированный рецепт шита (priest_128 d25417f, mage_128 тем же потоком):
- фронт-якорь: img2img с референса на хрома-зелёном 512 (denoise ~0.55); кадры =
  img2img 0.44–0.50 + openpose 0.90 + IPA 0.6, один seed на семейство видов;
- спина/бок: ОТДЕЛЬНЫЕ базы видов (img2img 0.78 от фронт-базы, лучший из 3
  сидов), кадры d0.50 + openpose 0.90 + IPA 0.5 — настоящие виды сзади без
  протечек лица;
- текстовые якоря на RD-модели проваливаются (13 txt2img = сцены данжа, чужие
  костюмы) — держать image-якорь;
- смерть «лёжа» не генерится ничем — рабочее: recoil + «extreme» кадры
  (denoise 1.0 + openpose 1.0 + depth 0.55 + IPA 0.7), потом постобработка:
  сплющить последний кадр 55%h×1.25w от ног = кучка, затемнённая копия = rest;
- скелеты и depth-карты — программно (skeletons.py);
- постпроцесс: фладфилл от цвета границы → крупнейшая компонента → чистка
  зелёных px → bbox от ног → scale → MEDIANCUT 64 цвета (убивает дрейф палитры
  между рядами).

**Вердикт пользователя (2026-09-12):** локальный ИИ-пайплайн (RD+ControlNet+IPA)
проигрывает процедурной рисовке по чистоте силуэта, стабильности палитры/костюма,
читаемости смерти; процедурные рисовальщики (класс barbarian.js/necromancer.js) —
стандарт для ФИНАЛЬНЫХ спрайтшитов. ИИ — только концепты, референсы поз, текстуры.

## Известные ограничения и заделы (игра)

- **Сохранений нет** — прогресс сессионный; между сессиями живут только
  `heroKey` (выбранный класс) и `libraryKinds` (открытия библиотеки) в
  localStorage. Задел: полное сохранение (мир/герой/квесты/умения).
- **Навигации к целям квестов нет** — трекер показывает счётчик, но не путь
  к цели (стрелка/миникарта-маркер) — задел.
- **Данжи без лута**: сундуки/ловушки/предметы не реализованы (арт в образце
  есть). Глубина 1..3; «дно» 3-го этажа — элитный вампир-страж.
- **Спящие механики дерева**: узлы «подземельной» зоны (ключи/комнаты/ловушки)
  изучаются как проводка — эффекты спят до данжевых механик; rage/reanimate/
  vampirism и прочие ключи бестиария ждут механик (flame/shadow/dash/charm/
  howl/summoning/crush/voidBlob/segmentation/invulnerability).
- **Заделы статов** (считаются, не применяются): сопротивление, сила воли,
  контрмагия; выносливость применяется только в heal.
- **Достижения** — третий режим Библиотеки в образце; у нас Библиотека пока
  только с врагами (объекты/достижения — задел).
- **Инвентаря нет** — вкладка «Экипировка» показывает куклу и статы; предметы
  и экипировка — задел (данные образца готовы).
- Состояние репозитория: удаления `wolf_128.json/png` и файлы `forWork/*`
  (UI/, art/, example/ и пр.) в рабочем дереве сознательно НЕ коммитятся.
