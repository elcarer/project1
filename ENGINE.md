# Документация движка (engine)

ECS-движок 2D-игры на **PixiJS 8.19** без сборщика и зависимостей (кроме самой PixiJS, подключённой локально).
Дата последнего рефакторинга: 2026-09-10. Бэкап кода до рефакторинга: `../engine-backup-before-refactor/`.

## Как запустить

ES-модули не работают с `file://` — нужен любой статический HTTP-сервер из папки `engine/`:

```bash
python -m http.server 8123
# открыть http://127.0.0.1:8123/
```

## Структура файлов

```
engine/
├── index.html                  # входная точка: подключает pixi.min.js и engine.js (type="module")
├── dll/pixi.min.js             # PixiJS 8.19 (локальная копия, включает AnimatedSprite)
├── images/
│   ├── bullets/all.png         # спрайтшит пуль 4×32px кадра (используется)
│   └── tiles/tile1.png         # тайл (пока не используется)
└── scripts/
    ├── data/units.js           # UNIT_CONFIGS (конфиги типов юнитов) + UNITS_EVENTS (константы событий)
    └── engine/
        ├── engine.js           # ECS-ядро, данные, системы, инициализация сцены (~640 строк)
        └── eventSystem.js      # шина событий on/off/emit/once/clear (пока НЕ подключена к игре)
```

## Архитектура: ECS-подход

Движок строго следует принципам Entity-Component-System:

- **Сущность (Entity)** — просто числовой ID (`0..99999`). Никаких методов и полей.
- **Компонент (Component)** — чистые данные без логики.
- **Система (System)** — вся логика; работает только с группами-запросами.

### 1. Данные компонентов

Два хранилища (SoA — structure of arrays, данные отделены от сущностей):

| Хранилище | Что лежит | Доступ |
|---|---|---|
| `COMPONENTS` | числовые данные в **типизированных массивах** (Float32/Uint8/Int32) | `COMPONENTS.positionX[id]` — O(1), кэш-дружелюбно |
| `DATA` | то, что не влезает в числа: ссылки на PIXI-спрайты | `DATA.spriteMap[id]` |

Компоненты: `positionX/Y`, `velocityX/Y`, `configId` (тип юнита), `radius`, `gridCellId`,
анимационные `currentFrame/totalFrames/animationSpeed/animationTime` (зарезервированы; при
использовании AnimatedSprite кадры считает сам спрайт, `animationSpeed` остаётся маркером
группы «animated»).

Регистрация компонента = битовая маска в `COMPONENT_MASKS`. **Лимит: 32 компонента** (Uint32Array).

### 2. Группы-запросы (queries)

`ECS.createQuery(world, имя, [компоненты])` собирает битовую маску требований. Система
перебирает только плотный массив `world.queries.<имя>.entities`, куда сущность попадает
автоматически при добавлении компонентов (триггер `updateQueries` на каждом изменении маски).
Удаление из группы — O(1) swap-and-pop, порядок сущностей в группе не гарантирован.

Активные группы: `movable`, `renderable`, `aliveUnits`, `animated`, `physics`.

### 3. Системы и порядок игрового цикла

```
app.ticker (каждый кадр):
  1. movementSystem     — movable:   позиция += скорость, отскок от краёв экрана
  2. spatialGridSystem  — physics:   очищает и перестраивает пространственную сетку
  3. collisionSystem    — physics:   столкновения кругов через сетку, расталкивание + упругий отскок
  4. animationSystem    — animated:  sprite.update(ticker) — кадры считает AnimatedSprite
  5. renderSystem       — renderable: спрайт.x/y = позиция из компонентов
```

### 4. Видовой слой (PixiJS)

- **Пулы спрайтов.** Спрайты не создаются/не уничтожаются в рантайме: при смерти сущности
  спрайт прячется (`visible=false`) и возвращается в пул своего типа. Пулы **раздельные**:
  `STATIC_SPRITE_POOLS[typeIndex]` для `PIXI.Sprite` и `ANIMATED_SPRITE_POOLS[typeIndex]`
  для `PIXI.AnimatedSprite` — смешивание недопустимо (разные классы, разное поведение).
- **Анимация.** Мигрировано с «массива спрайтов-кадров» на `PIXI.AnimatedSprite(textures, false)`:
  1 объект сцены на юнита вместо N, нет циклов скрытия кадров. `autoUpdate=false` — кадрами
  управляет `animationSystem` (детерминированный порядок цикла).
  ⚠️ **Нюанс API:** в PixiJS 8.19 `AnimatedSprite.update(t)` ждёт **объект тикера** (читает
  `t.deltaTime`). Передача числа даёт NaN в текущем кадре → спрайт исчезает из рендера.
- **Текстуры.** Два источника: программный атлас (`createProgrammaticSpritesheet` — кадры
  Graphics запекаются в один RenderTexture, кадры делят общий источник) и загрузка
  спрайтшита из PNG (`loadSpritesheetFromImage`).

### 5. Пространственная сетка (SpatialHashGrid)

Равномерная сетка с ячейкой 32px поверх `Map`. Каждый кадр: `clear()` возвращает массивы
ячеек в пул `freeArrays` (переиспользование, минимум мусора для GC) → `insert()` по
`getCellKey(x,y) = col + row*cols`. `collisionSystem` для каждого объекта проверяет только
свою ячейку и 8 соседних; повторные пары отсекаются условием `idA < idB`; дистанция —
сравнение квадратов (без `Math.sqrt` до момента фактического столкновения).

## Отладка

На странице доступен глобальный хендл (после `init()`):

```js
window.__ENGINE  // { app, ECS, world, COMPONENTS, DATA, SpatialHashGrid,
                 //   particleContainer, STATIC_SPRITE_POOLS, ANIMATED_SPRITE_POOLS }
```

Пример: `__ENGINE.world.queries.animated.entities.length`

## Что изменено в рефакторинге 2026-09-10

1. **Исправлен критический баг сетки коллизий:** `cells` был `Map`, но читался/писался через
   квадратные скобки (`cells[key]`) — Map при этом не использовался, а `clear()` не очищал
   накопленное → ячейки росли вечно (утечка памяти + ложные столкновения). Теперь честный
   `Map` + переиспользование массивов ячеек.
2. **Анимация переведена на `PIXI.AnimatedSprite`** (по согласованию): 150 юнитов × 4 кадра
   = 600 спрайтов стало 150 объектов; убраны циклы скрытия/показа кадров.
3. **Разделены пулы** статических и анимированных спрайтов (раньше общий пул мог выдать
   Sprite там, где ожидался массив кадров, — латентный краш при смерти юнитов).
4. `removeEntity`: удаление из `world.entities` через swap-and-pop вместо `splice` (O(1)).
5. `gridCellId` урезан с 1 000 000 до 100 000 элементов (согласовано с лимитом сущностей, −3.6 МБ).
6. `defineComponent`: добавлен default-случай (Float32Array + warning) вместо тихого `undefined`.
7. **Переименования:** `pozitionX/Y → positionX/Y`, `eventSistem.js → eventSystem.js`.

Проверено в браузере: рендер 250 юнитов, движение, анимация кадров, удаление сущностей,
синхронность всех групп-запросов, отсутствие NaN в физике, корректное наполнение пулов.

## Известные ограничения и идеи на будущее

- **32 компонента максимум** (битовая маска Uint32). При расширении — перейти на Uint32Array
  из двух половин или таблицу соответствий.
- `ECS.nextId` — глобальный, а не на world: несколько миров будут конфликтовать по ID.
- `eventSystem.js` готов, но не подключён (константы `UNITS_EVENTS` уже объявлены в units.js).
- Стенки отскока захардкожены как `±8` в movementSystem — вынести в конфиг/компонент.
- `getCellKey` с отрицательными координатами может дать коллизии ключей за пределами экрана.
- `images/tiles/tile1.png` не используется.
- Нет git и тестов; перед крупными изменениями стоит `git init` (бэкап-копия уже есть).
